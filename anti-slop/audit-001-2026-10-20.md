## Detailed Findings & Proposed Solutions

### Finding #01 — Fictional Collaborator Avatars in Hero Section
- **Rule Violated**: R-23 (Clarification & Visual Assets), R-38 (Real Content or Honest Placeholder).
- **Priority**: HIGH (Hard Gate).
- **Reason**: The hero component renders an avatar cluster labeled `FN`, `JD`, `ST`, `UI`, `IS` as "collaborators", which was copied directly from the visual reference mockup.
- **Proposed Action**: Remove the fictional avatar cluster completely. Replace with authentic developer metadata: Ferry's focus areas, primary technical stack badges, or a clean editorial narrative aligned with `data/site.json`.

### Finding #02 — Handling of Optional Repository & Online Demo Links
- **Rule Violated**: R-26 (Interactive Elements), R-38 (Real Content or Honest Placeholder).
- **Priority**: HIGH (Hard Gate).
- **Reason**: The UI shows static dead indicators like "No public demo" and does not cleanly handle optional project links as requested by the user.
- **Proposed Action**: Standardize `links` schema across `data/projects.json` (`demo` / `onlineUrl` and `repository` / `repoUrl`). If a link exists, render a clean, accessible button or link. If empty or absent, completely omit the element from the card and detail page (no dead buttons or "no demo" badges).

### Finding #03 — Design Direction Violation (Sterile Light Mode vs. Dark Editorial Direction)
- **Rule Violated**: R-37 (Design Direction Required), R-01 (Color & Gradients).
- **Priority**: HIGH (Hard Gate).
- **Reason**: The codebase switched to a generic light theme (`--background: #ffffff`, `bg-white`), directly violating the project's art direction in `docs/DESIGN_GUIDE.md` and `AGENTS.md` which requires a dark editorial aesthetic: near-black canvas (`#08090B`), surface layers (`#101216`), fine borders (`#292D35`), high-contrast typography, and cobalt blue accents (`#6D83FF`).
- **Proposed Action**: Restore CSS variables and Tailwind classes to the dark editorial tokens defined in `docs/DESIGN_GUIDE.md`. Ensure strong contrast ratios (WCAG AA).

### Finding #04 — Project Cover Image & Interactive Detail Preview Slider
- **Rule Violated**: R-27 (UI States), R-38 (Real Content or Honest Placeholder), C-3 (Content-Driven Composition).
- **Priority**: HIGH (Hard Gate).
- **Reason**: Projects currently depend on synthetic CSS mockup components (`visual.type`) without first-class support for 1 cover image and optional multi-image previews that users can slide/swipe through on the detail page.
- **Proposed Action**:
  - Update `data/projects.json` schema and TypeScript interfaces: add `coverImage?: string` and `previewImages?: string[]` (or `gallery?: string[]`).
  - Implement an accessible, interactive preview slider/carousel on `/projects/[slug]` with previous/next navigation, slide indicators, and swipe support.
  - If preview images are provided, allow smooth navigation between them. If only 1 cover image is provided, display the single cover image cleanly. If no image is provided, display a restrained editorial graphic placeholder without fake traffic-light slop.

### Finding #05 — Contact Form & Contact Page AI-Slop Styling
- **Rule Violated**: R-03 (Mobile Responsiveness), R-27 (UI States), R-32 (Keyboard Accessibility).
- **Priority**: HIGH (Hard Gate).
- **Reason**: `ContactForm` is styled as a generic white box with raw inputs, basic focus rings, and boilerplate placeholder copy ("Alex Morgan").
- **Proposed Action**: Redesign the contact form to match the dark editorial aesthetic: refined inputs with subtle dark surface backgrounds (`#171A20`), crisp borders (`#292D35`), distinct focus states with cobalt accents, responsive tap targets (min 44px), proper error/success states, and clear fallback mailto link.

### Finding #06 — Decorative Status Dots with Endless Pulse
- **Rule Violated**: R-19 (Animations), R-31 (Purpose of Marks).
- **Priority**: MEDIUM (Purpose-Gate).
- **Reason**: Endless `animate-ping` pulses on green status dots across contact, hero, and CTA sections borrow system-indicator language without actual real-time status.
- **Proposed Action**: Remove the `animate-ping` layer. Keep a solid, refined indicator dot or clean typographic badge indicating status without gimmick animation.

### Finding #07 — Fake macOS Traffic-Light Window Dots
- **Rule Violated**: R-05 (Layout & Page Structure), R-06 (Typography).
- **Priority**: MEDIUM (Purpose-Gate).
- **Reason**: The project preview mocks a browser/terminal window with red, yellow, and green circular buttons that do nothing.
- **Proposed Action**: Replace the fake OS window styling with genuine editorial framing: clean aspect ratio container, subtle border, authentic preview header, and interactive controls when genuine previews exist.

### Finding #08 — Capsule Badge Trend Stacking
- **Rule Violated**: R-09 (Badges), R-31 (Purpose of Marks).
- **Priority**: MEDIUM (Purpose-Gate).
- **Reason**: Capsule pills with border, dot, and uppercase tracking duplicate adjacent heading text.
- **Proposed Action**: Simplify badges into clean, semantic tags without unnecessary decorative dot-and-border stacking.

### Finding #09 — Uniform Card Rhythm & Checklist Clones
- **Rule Violated**: R-14 (Feature Cards), R-05 (Layout & Page Structure).
- **Priority**: LOW (Quality Locks).
- **Reason**: Projects and skills use identical card layouts and repetitive checkmark icons, flattening visual rhythm.
- **Proposed Action**: Introduce varied editorial rhythm between featured flagship projects and secondary project cards; refine typography and metadata hierarchy.
